# v2 language comparison, mvccs_acid with and without the translator's IR, 2026-11-20

- Run: `v2-lang-1795213722702`
- Commit: `91f517f` (`reasoning 1.13.3`). The tree the run read is that
  commit plus the 1.14.0 changes committed with this report: the
  language runner's arms, `ir_prep.pl`, `v2_setting/2`, and the IR
  check's logical form.
- Model: `claude-sonnet-5-5`, provider `anthropic`, effort `low`,
  `max_tokens` 16 000, no temperature (the model refuses one)
- Task: `mvccs_acid` (a hard task, `v2_hard_task/1`), repair cases 1-5,
  7, 9, 10, held-out cases 6 and 8, exact output
- Languages: C, Python, cocolog, SWI-Prolog
- Arms: `plain` (the language's requirement) and `ir` (the same
  requirement, byte for byte, and then the translator's IR note)
- Trials: 3 per language and arm, seed `20261117`; the 8 jobs of a trial
  are shuffled together
- Budget: up to 3 generator calls per cell; a case has 5 s in C and 10 s
  in the other languages
- Files: `ir-mvccs-20261120/bench.jsonl` (the benchmark),
  `ir-mvccs-20261120/ir-prep.jsonl` (the translation phase),
  `ir-mvccs-20261120/mvccs_acid-LANG.ir` (the four notes the `ir` arm read)
- Total: 24 cells, 38 generator calls, 453 562 tokens, 626.9 s of cell
  time

## The translation phase (not in the benchmark's figures)

The translation was done first, by `ir_prep.pl` on the endpoint's store
(`coding/endpoint/store`). It read every sentence of each language's
requirement and asked the model to check each reading. The benchmark then
read the four notes from files and called no translator, so no
translation call, token or second is in the results below.

| run | calls | prompt tokens | completion tokens | seconds |
|---|---|---|---|---|
| 1 | 9 (C 3, Python 3, cocolog 2, SWI-Prolog 1) | 17 035 | 1 310 | 22.75 |
| 2 | 0 | 0 | 0 | 5.76 |
| 3 | 0 | 0 | 0 | 5.58 |

The requirements of the four languages share all their sentences but the
first. So a judgment made for one language can change a note made before
it: run 2 read the C note again at 3 151 characters, where run 1 had
written 3 365. Run 3 made no call and wrote the same four notes as run 2.
The benchmark read those notes:

| language | sentences | read (each one rewritten first) | unread | note characters |
|---|---|---|---|---|
| C | 14 | 4 | 10 | 3 151 |
| Python | 14 | 4 | 10 | 3 151 |
| cocolog | 14 | 5 | 9 | 4 394 |
| SWI-Prolog | 14 | 5 | 9 | 4 403 |

The C and Python notes are the same. The cocolog and SWI-Prolog notes also
read their first sentence ("Write a complete cocolog program whose main/0
reads standard input and writes standard output."). The command table is
one sentence to the splitter, and it is not read in any note.

An earlier batch of the phase (11 calls, 14 394 + 2 563 tokens) was
discarded before the benchmark. In that batch, the check showed the model
only the English said back. Two wrong readings passed, because they said
back the same sentence: "Blank lines are ignored." with "lines" as the
verb, and "Read commands from standard input…" with "Read" as a noun.
Since 1.14.0 the check shows the logical form too, and tells the model to
judge each word's role. The stored "right" verdicts of the old check were
taken out, and the phase was run again. Its new rewrites, such as "The
program ignores blank lines.", are in the notes above.

## The held-out failures

Each of the five held-out failures is held-out case 8, and no other case:

```text
b T1
b T2
i T1 5
c T1
d T2 5
c T2
g 5
v
```

The expected output is `no` and `2`: T2's deletion of 5 removes the 5
that T1 committed. Each failing program prints `yes` and `2`. Key 5 is not
in T2's view (T1 committed after T2 began), so the program ignores the
deletion, because "a deletion of an absent key is ignored". Then T2's
commit has no change to apply. The expected output reads "absent" as
"absent from the latest committed version when T2 commits". The
requirement says neither, and its other sentence ("An insertion of a key
already visible is ignored") is about the view. So this case tests how a
program reads one ambiguous sentence, as well as MVCC. (The 2026-11-17
diagnostic run failed repair case 3, the snapshot visibility, and never
ran the held-out cases. In this run, every program that reached the
held-out cases passed case 3.)

| arm | case 8 failed | language and trial |
|---|---|---|
| plain | 1 | cocolog 2 |
| ir | 4 | cocolog 1, 2, 3; SWI-Prolog 1 |

The note's rewrite of the sentence ("If a key is absent, the program
ignores a deletion of the key.") keeps the same ambiguity. With three
trials a cell, this run cannot tell whether the note makes the view
reading more likely.

## What this run says, and what it does not say

- In this run, the `ir` arm took fewer generator calls (16 against 22),
  4.5 % fewer tokens and 18 % less time. Its first programs passed more
  often (5/12 against 3/12), and every one of its final programs passed
  all eight repair cases (12/12 against 10/12).
- Its final pass rate was one cell lower (8/12 against 9/12). All of the
  difference is the case-8 failures, three of them in cocolog.
- Without cocolog, the `ir` arm passed 5/9 at pass@1 and 8/9 at the end,
  and the `plain` arm 2/9 and 7/9. This split was made after the run, so
  it is a description, not a test.
- None of these differences is significant at three trials a cell. For
  example, Fisher's exact test gives p = 0.67 for pass@1 (5/12 against
  3/12) and p = 1.0 for the final pass (8/12 against 9/12).

Confounds:

- Case 8 is ambiguous (above), and it is half of the held-out set.
- No case checks that a program uses a B-tree. The failing cocolog program
  of `ir` trial 1, for example, keeps each version as an ordered list.
- The note goes in the user prompt after the requirement, so the `ir`
  arm's prompt is longer and differently placed. A note of the same length
  with no IR in it was not tried.
- The translator read only 4 or 5 of the 14 sentences. It did not read
  the command table, which holds most of the semantics.
- The model has no temperature setting, so each trial is a sample of a
  generator that is not deterministic. The trials of one cell are not
  repeats of one output.
- A case has 5 s in C and 10 s in the other languages (the stated
  confound of the language runner).

## How to run it again

```sh
CODING_ENDPOINT_IR_API=anthropic CODING_ENDPOINT_IR_KEY=... \
CODING_ENDPOINT_IR_MODEL=claude-sonnet-5-5 \
COCOLOG_LIBRARY="$(dirname "$PWD"):$PWD/../cocolog/library" \
    ../cocolog/cocolog --embed coding/endpoint/store \
        -s coding/bench/v2/ir_prep.pl -- \
        --tasks mvccs_acid --langs c,python,cocolog,swipl --out DIR
CODING_ENDPOINT_KEY_ENV=... CODING_BENCH_PROVIDER=anthropic \
CODING_BENCH_MODEL=claude-sonnet-5-5 \
CODING_BENCH_BASE_URL=https://api.anthropic.com/v1/messages \
    ./coding/bench/v2/lang.sh --run --tasks mvccs_acid \
        --langs c,python,cocolog,swipl --arms plain,ir --ir-notes DIR \
        --trials 3 --seed 20261117 --out FILE
```

On the store committed with this report, the translation phase makes no
call and writes the four notes above.
