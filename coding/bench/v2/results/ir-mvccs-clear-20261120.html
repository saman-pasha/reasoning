reasoning 1.15.4 · coding bench v2 · 2026-11-20 to 21

What the reasoning library adds to a coding prompt

One hard task, mvccs_acid (a multi-version B-tree with transactions and snapshot isolation), written by claude-sonnet-5-5 at effort low in five lanes. Each cell got the prompt forwarded as it is, the prompt with the reasoning pre-pass (its default two checks, or, in a run of its own, every check), or the prompt with the pre-pass and the translator's IR. Ten trials a cell, up to three model calls each.

424 cells in seven runs, 811 generator calls, 8 119 201 tokens and 3 h 52 min of cell time: $33.88 at list prices, $34.23 with the translation phase and two requests sent again by hand.

What the runs show

The pre-pass's checks change nothing measurable here, two of them or all of them.

For this requirement the pre-pass adds input and output checks and no "What the request is about" note, because the reasoner parsed no terms of the text. The keyword reader found 13 checks in the C requirement and 12 in each other lane's, and the endpoint's default sends only the first two, the generic input and output checks (341 characters; 404 for Python). In C and the three Prolog lanes the checks after them name the task: the 2-3-4 tree's split, versions, snapshots and the atomic commit. Python's do not. Run A, which ran the two reasoning arms together, gives 13/50 first-attempt passes for + reasoning and 14/50 for + reasoning + IR (p = 1.0). In the SWI-Prolog rerun, which ran all four arms together, prompt forwarded and + reasoning both pass 0/10 at the first attempt. In cocolog without its guide, also run as one, they pass 7/10 and 5/10. With every check, in a run of its own with the prompt forwarded, the arm passed 19/50 at the first attempt and the prompt forwarded 20/50 (p = 1.0).

The IR note helps the two Prolog lanes at the first attempt, and not C or Python.

In the clear-text run, IR only against the prompt forwarded: cocolog 9/10 against 3/10 (p = 0.020), SWI-Prolog 5/10 against 0/10 (p = 0.033), all four lanes 21/40 against 10/40 (p = 0.021). C and Python do not move. The SWI-Prolog rerun points the same way, 3/10 against 0/10 (p = 0.21). With fewer repair rounds the IR arm also spent fewer tokens and seconds in those lanes. cocolog without its guide, on its two-line prompt, does not show it: 6/10 against 7/10. These tests were not chosen before the run: read them as a description.

Checks in front of the IR do not add to it.

In the SWI-Prolog rerun the IR alone passed 3/10 at the first attempt and + reasoning + IR 1/10, with 75 % more tokens. In cocolog without its guide, whose four arms also ran as one run, both passed 6/10 with about the same tokens. In C, Python and guided cocolog the two IR arms ran an hour apart, so they are not compared here.

The final pass hides the differences.

Almost every cell of C, Python, both cocolog lanes and SWI-Prolog passes within its three calls (final 38/40 to 40/40 a lane). What the arms change is how often the first program is right, and so the calls, tokens and seconds a correct program costs.

Two lines do the cocolog guide's work on this task.

With the two lines in its short prompt, cocolog without its guide passed 24/40 at the first attempt and 40/40 in the end. The guided lane passed 23/40 and 39/40, and spent 2 264 582 tokens where the lane without the guide spent 338 045, 6.7 times fewer (62 calls against 56). The rows come from runs on the same text but on different days, so read this as a description, not a paired test. Without both lines the same lane passed none of its 60 first attempts: 20 with neither line, 40 with the stream import alone.

cocolog without its guide spent fewer tokens than Python.

Over its four arms it spent 338 045 tokens where Python spent 359 114, 6 % fewer, and fewer in three of the four arms (all but + reasoning + IR, 104 528 against 103 670). Its first program was right 24 times in 40 and Python's 13 times, so it needed 56 calls where Python needed 68. Python's rows come from runs on another day, so read this as a description.

SWI-Prolog's low first-attempt rate is partly its prompt's.

Its user message is the requirement alone. Every cocolog lane's begins "Write a complete cocolog program for this requirement." In the SWI-Prolog rerun, 22 of the 40 first replies began with English design notes before the code and did not load; no first reply of either cocolog lane did. So the gap at the first attempt between SWI-Prolog and cocolog without its guide, 4/40 against 24/40, is not only a gap between the two languages.

Why the IR note saves tokens in C and costs tokens in Python

The first run's report showed fewer tokens for the IR arm in C. The clear-text run shows the same in C, and more tokens in Python, as the first run also did. The direction is the same in both runs; only the size changed. Each total is its calls times its tokens a call:

The note makes every call dearer: it adds 1 435 prompt tokens to a call, in C and in Python (measured on the cells of one call). It makes a cell cheaper only by saving repair calls, and a repair call is expensive: it sends the requirement, the note, the previous program and the failure report, and the model writes a whole new program. In the clear-text run a C cell of one call spent about 5 750 tokens and a cell of two calls about 15 800; in Python about 3 800 and 10 200.

  • C: the note made the first program right 5 times in 10 against 4, and the arm made 5 repair calls against 9. Its calls fell by 21 %, its tokens a call rose by 13 %, and its tokens fell by 10 %.
  • Python: the first program was right 2 times in 10 against 3, and the arm made 9 repair calls against 7. Its calls rose by 12 %, its tokens a call by 40 %, and its tokens by 57 %.
  • The first run: C saved two calls of six, which paid for the note; Python saved one, which did not. At three cells an arm one repair call more or less moves an arm's tokens by about 30 %, and the first run read the old text: its report says no difference in it is significant.

On this task the note does not make C's or Python's first program right more often, and without that it only adds tokens. The same rule makes cocolog without its guide spend fewer tokens than Python: its first program was right 24 times in 40 and Python's 13, so it made 56 calls where Python made 68, and spent 6 % fewer tokens though each of its calls spent 14 % more.

  • Python got none of them. Its twelve checks are Python's own phrasings of generic checks: integers, max and min, recursion depth, sort order, word splitting, and "An error the task names is raised with raise ValueError("...")". The cases expect the program to print the word error; the requirement does not say what an error prints. Python rose from 4/10 to 6/10 (p = 0.66), with 4 % fewer tokens.

The arms

Each arm is one of the coding endpoint's settings. The notes are the endpoint's own text, written before the run by ir_prep.pl and read from files, so the benchmark calls no translator and no model for them. They go after the requirement in the user prompt; the endpoint puts them in the system prompt after the guide.

The lanes are C, Python, cocolog with its 19 000-token guide, cocolog with a short prompt in place of the guide, and SWI-Prolog with a short prompt. The requirement is the same in every lane but its first sentence, which names the language.

Why cocolog with the IR failed every cell in the first run

The first run (reasoning 1.14.0, 24 cells) failed held-out case 8 five times, three of them in all three cocolog IR cells:

input
b T1
b T2
i T1 5
c T1
d T2 5
c T2
g 5
v
expected · what the failures printed
no      yes
2       2

T2 deletes the 5 that T1 committed after T2 began. The expected answer applies the stale deletion at commit. The failing programs ignored it, because 5 was absent from T2's view.

The text said "a deletion of an absent key is ignored" and did not say absent from what. Running case 8 on every kept attempt showed that the view reading came only from the Prolog lanes: 0 of 19 C and Python attempts, 5 of 15 Prolog attempts. The Prolog programs kept each view as a sorted set and either ignored the deletion when it was staged or computed the commit as view minus snapshot. All four IR notes held only the rule that leads there ("If a key is absent, the program ignores a deletion of the key"); the sentence that the last committer wins was among the sentences the translator did not read. Since reasoning 1.14.1 the text says the rule: a transaction keeps one staged change per key, and the commit applies each to the latest version. On that text no attempt of any lane read the view again, and cocolog with the IR passed 9/10 at the first attempt.

Two lines a model not trained on cocolog needs

cocolog is this project's own Prolog, and no model was trained on it. Without the guide, claude-sonnet-5-5 writes the dialect it knows best, SWI-Prolog 7, and said as much in a repair reply: "I can't see which Prolog dialect cocolog is." cocolog runs nearly all of that code. Two of its defaults are not SWI-Prolog 7's. Without the lines that change them, no first attempt passed even the first case:

:- set_prolog_flag(double_quotes, string).
:- use_module(library(stream)).

Fixes made on the way

  • 1.14.0, the IR check shows the logical form. The model judged each reading by its English said back, and two wrong readings said back the same sentence ("Blank lines are ignored." with lines as the verb). The check now shows the terms and asks for each word's role.
  • 1.14.1, the task's text states which deletion a commit applies. No expected output changed; runs before and after are not comparable.
  • 1.15.1, a reply with no text is sent again, once, and counted. The model's safety classifier refused three repair attempts of the some 400 calls made by then, category reasoning_extraction ("reverse engineering or duplicating model outputs"; a repair prompt sends the model its own previous program). Two came back as a thinking block and no text. Each was a generator failure that counted no tokens. The same requests sent again were answered, and server-side fallback does not retry this category on this model. Now the child sends it once more, counts its tokens and names its stop reason in the row. The SWI-Prolog lane was run again under this fix and met no empty reply.
  • 1.15.2 and 1.15.3, the no-guide prompt names the two lines. The first no-guide prompt (1.15.0) said only that the program is cocolog. In run A its 20 cells failed all 60 attempts: 46 programs stopped at an unknown stream predicate (read_line_to_string/2, get_char/1, get_code/1, read_line_to_codes/2), 9 printed nothing, 4 ended with main/0 failing, and 1 reply was empty. 1.15.2 added the stream import, and no program stopped at a stream predicate again. But every first attempt still failed case 1, whose input is the one command v: 26 printed nothing and 14 printed error, because no clause head written with "v" matched the string that was read. In the end 18 of 40 cells passed, none at the first attempt. Run offline on 12 of those first attempts, the double_quotes flag alone made 9 of them pass all ten cases. 1.15.3 added that flag as the second line.

Limits of these runs

  • Ten trials a cell. A difference of two or three cells in ten is inside the noise; only the clear-text run's pooled IR effect passes p < 0.05.
  • The arms of C, Python and guided cocolog come from two runs an hour apart (prompt forwarded and IR only in one, the two reasoning arms in the other). SWI-Prolog and cocolog without its guide ran all four arms in one run each.
  • One task. The reasoning pre-pass reads controlled English; this requirement is not, so its about note is empty, and the default sent 2 of the 12 checks the keyword reader found (13 for C), the two generic ones. Every check, sent in a run of its own, changed nothing either. A request the reasoner can read is where the pre-pass would show more.
  • The notes sit in the user prompt, not in the system prompt as the endpoint puts them.
  • The lanes' prompts differ in more than the language: the SWI-Prolog lane's user message is the requirement alone, and every cocolog lane's begins with an instruction to write the program.
  • The translator read 4 to 6 of the 14 sentences. The IR note never held the command table, which holds most of the rules.
  • No case checks that the program uses a B-tree, and C gets 5 s a case where the others get 10 s.
  • The model takes no temperature; trials are samples of a generator that is not deterministic.
