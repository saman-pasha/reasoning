Which reasoner note helps Python's first program

One hard task, mvccs_acid (a multi-version B-tree with transactions and snapshot isolation), written in Python by claude-sonnet-5-5 at effort low. Each cell got the requirement alone, or the requirement and one note: the requirement said again in controlled English, or what three of the reasoner's readers make of that text, or the translator's IR. Twenty trials an arm, up to three model calls each.

120 cells in one run, 213 generator calls, 1 159 412 tokens and 39 min of cell time: $5.75 at list prices.

What the run shows

No reader's note made the first program right more often.

reason_text/2's terms passed 7/20 at the first attempt, as the requirement alone did. The outline of reason_topics/2 passed 5/20, reason_concepts/2's list 3/20 and the translator's IR 3/20. No arm differs from the requirement alone at p < 0.05 (Fisher's exact test, two-sided).

The readers' input did best: the requirement in controlled English.

It passed 12/20 at the first attempt against 7/20 (p = 0.21). It made the fewest calls, 29 against 34, and spent only 3 % more tokens, though each call carried 2 590 characters more. Every other note spent 42 % to 89 % more tokens than the requirement alone.

One unnamed word decides the first attempt.

Python's first programs fail almost only at the error case, whose expected output is the word error. The requirement never says what an error prints, and most failing programs print nothing there. 14 of the controlled text's 20 first programs print error, against 8 of 20 with no note.

Two cells failed for the safety classifier, not for their programs.

Both repair calls of two concepts cells were refused, category reasoning_extraction, and each request sent again was refused again. That is why concepts passes 18/20 at the end where every other arm passes 20/20.

The notes

The readers read controlled English, and the requirement is not controlled English. reason_text/2 reads none of its 14 sentences: not with the grammar, not with the tagger, and in live mode only one, wrongly. A note made from the requirement as it is would be empty. So the notes come from a controlled restatement: 64 sentences the grammar reads, written by hand from the requirement's text alone and never from the cases or their expected output.

It says what the requirement says and nothing more. The requirement says "error if T is not active" and never what an error prints, so the restatement says Every transaction that is not active causes an error. and not that the program prints error. What the grammar cannot say is left out, for example that each command's output goes on its own line.

reason_prep.pl reads the restatement with the grammar alone (no tagger, no saved rewrite, no model) and writes the notes. No model was called for them, and no token of theirs is in any figure here. A reading that is the grammar's and not the sentence's meaning stays as it is: Every transaction that is active may commit. becomes may_commit/1.

Why Python's first programs fail

Almost every failure is at the error case. It sends r, i, c and a for a transaction that has not begun, then b twice, and it expects error five times.

Run on that case's input, 11 of the 13 failing programs with the requirement alone print nothing at all, and 2 stop with a traceback. Of the 7 controlled-text programs that failed the case, 6 print nothing and 1 prints error once.

So on this task a note helps the first program when it makes the model print a word the requirement never names. The controlled text says "causes an error" in two sentences of its own. The terms say the same as two rules among 66, and the concepts and the outline put it among 94 and 53 lines. The earlier runs show the same failure: in the clear-text run, 24 of Python's 27 failed first programs failed only the error case.

Limits of this run

  • One task and one language. Here a note helps or hurts through one word that the cases expect. A task whose failures are not one unnamed output would test the readers in another way.
  • Twenty trials an arm. A difference of five cells in twenty is inside the noise (p = 0.21).
  • The restatement was written by hand, by the assistant that ran the benchmark, before the run and from the requirement alone. Its cost is not counted, and another writer would make another text. It tests what a controlled text gives the model, not what a reader gives it.
  • The IR note reads the requirement as it is, not the restatement.
  • The notes sit in the user prompt, not in the system prompt as the coding endpoint puts them.
  • The model takes no temperature. Trials are samples of a generator that is not deterministic.
