Controlled English in Python codegen, over three runs

Does the requirement, said again in controlled English after the requirement itself, make Python's first program right more often? Three runs asked it, each with 60 trials an arm and its tests written down before it. The first found the effect, the second did not, and the third decides it.

This run: 120 cells, 191 calls, 898 638 tokens, 36 min of cell time, $4.90. The three runs: 360 cells.

The answer

Over three runs, yes: 104/180 first programs right with the note, against 79/180 without (58 % against 44 %), p = 0.0058.

Cochran–Mantel–Haenszel, one-sided, each run a stratum, chosen before the third run. The common odds ratio is 1.75.

This run alone does not pass its own test: 33/60 against 24/60, p = 0.072.

It points the same way as both earlier runs. A single run of 60 an arm is too small to show a gain of this size every time.

It costs about as much as it saves.

Over the three runs the note saved 8 % of the calls and spent 5 % more tokens: each call carries about 900 tokens more, and fewer repair calls are needed.

How the first programs failed

As in every Python run, almost only at the error case, which expects the word error that the requirement never names: 35 of 36 failing first programs with the requirement alone, 26 of 27 with the note. The note's gain goes through that case, but the count of first programs with the text "error" moves from run to run as much as the passes do: 39, 34 and 34 with the note, and 27, 36 and 30 without.

Limits

  • One task, one model, one language.
  • The pooled test was chosen after two of its three runs were known, and this run alone did not pass its own test.
  • The restatement was written by hand, by the assistant that ran the benchmark, from the requirement alone; another writer would make another text.
  • The same note harms guided cocolog and does nothing in C and in cocolog without its guide.
